### Signatures and pattern recognition
- ==Signature matching== looks for known bytes, strings, or hashes
  - Antivirus hashes, IDS rules (Snort, Suricata), ==YARA== rules
  - Fast, explainable, almost no false positives
  - Misses anything new or reworded; one changed byte can defeat a hash
- ==Pattern recognition== is a trained model scoring how much an input resembles examples it learned from
  - Phishing classifiers, malware family classifiers, DGA domain detection, alert grouping
  - Catches variants that no rule names yet
  - Gives a probability instead of a yes or no, so someone has to pick a threshold
- AI adds pattern recognition alongside signatures, and can draft new YARA or Sigma rules for an analyst to test

```yaml label="lure.yar"
rule Lure_Account_Verify
{
  strings:
    $a = "verify your account" nocase
    $b = "password expires today" nocase
  condition:
    any of them
}
```

- The same three email subjects through the YARA rule and a small scikit-learn classifier (character n-grams, logistic regression, trained on 16 labeled subjects)

```console label="python3 subjects.py"
$ python3 subjects.py
yara  ml    subject
HIT   0.84  Verify your account by Friday
miss  0.85  Re-confirm your login credentials
miss  0.20  Change board moved to Friday
```

- The reworded lure slips past the signature; the model still scores it 0.85
  - Sixteen examples make a demo; production classifiers need thousands and regular retraining

### Anomaly detection and fraud detection
- ==Anomaly detection== learns what normal looks like and flags what does not fit
  - No labeled attacks needed (unsupervised)
  - User and entity behavior analytics (==UEBA==): logins, data volumes, process trees, network flows
- ==Isolation Forest== builds random trees that split the data; an outlier is cut off in very few splits

:::figure 3.1-isolation-forest.svg | A login far from the cluster is isolated after two random cuts. A typical login needs many more, so it scores as normal.

- 500 synthetic logins (hour, failed tries, distance from the usual city, MB downloaded) plus three planted events, 500 to 502

```console label="python3 logins.py (scikit-learn)"
$ python3 logins.py
500 ANOMALY -0.86  3h  9fail 8400km 2600MB
501 ANOMALY -0.74  2h  0fail   12km 1900MB
502 ANOMALY -0.67 11h 14fail    3km   35MB
375 ANOMALY -0.64 15h  3fail    5km   40MB
213 ANOMALY -0.63  6h  0fail   31km   39MB
flagged: 6 of 503
```

- All three planted events rank first; events 375 and 213 are ==false positives==
  - `contamination=0.01` told the model to flag about 1% of rows; that setting is the alert budget
  - Unusual is not the same as malicious: a traveling admin also looks odd
- ==Fraud detection== combines both approaches
  - Supervised models trained on confirmed fraud and chargebacks; anomaly scores for new schemes
  - Card transactions, account takeover, fake account sign-ups, payroll and gift card scams
  - Features: velocity (transactions per minute), device fingerprint, impossible travel, new payee
  - Fraud is rare (heavy class imbalance), so judge models on precision and recall; accuracy hides the rare cases

### Code quality, linting, and vulnerability analysis
- ==Code quality and linting== with AI
  - Traditional linters (`ruff`, `eslint`, `shellcheck`) apply fixed rules
  - An AI reviewer explains why a pattern is risky and drafts the fix in a pull request comment
  - Keep the deterministic linter in CI; the AI review is advice that a human accepts or rejects
- ==Vulnerability analysis==
  - Triage SAST and dependency scanner output: which findings are reachable, which are noise
  - Explain a CVE in the context of your code; draft a patch and a test
  - Rank the backlog with exploit likelihood (EPSS) and asset value
  - Find new bugs: Google's Big Sleep agent found an exploitable SQLite flaw in 2024; DARPA's AI Cyber Challenge (AIxCC) final in 2025 scored systems that found and patched bugs on their own
- Limits: models report plausible flaws that do not exist (reproduce before filing), and code sent to a hosted model leaves your boundary

### Automated penetration testing and threat modeling
- ==Automated penetration testing==: an agent plans steps, runs tools, reads results, and chooses the next step
  - XBOW, an autonomous web testing system, topped HackerOne's US leaderboard in 2025
  - Breach and attack simulation (BAS) platforms replay known techniques on a schedule
- Run it like any pen test
  - Written authorization and scope; an allowlist of targets enforced by the tooling, not by the prompt
  - Human approval for anything destructive; full logging of commands
  - Findings are leads until a person confirms them
- ==Threat modeling== with AI
  - Feed in an architecture description or data flow diagram; get a first draft of STRIDE threats per component
  - Map threats to MITRE ATT&CK and MITRE ATLAS techniques; suggest mitigations
  - Fast first draft for a design review; it misses business logic and context only the team knows

### Incident management, summarization, and translation
- ==Incident management==
  - Group related alerts into one incident; enrich with asset owner, threat intel, past tickets
  - Suggest the next playbook step; draft the status update and the post-incident report
- ==Summarization==: turn a long timeline, alert, or log excerpt into a few lines for a manager or shift handoff
- ==Translation==: read phishing, threat intel, and ransom notes written in other languages; write user notices in theirs
- Both run on a small local model below (`qwen2.5:0.5b`, Ollama, temperature 0); the incident data never leaves the host

```console label="Summary from qwen2.5:0.5b"
08:02 EDR alert: WS-114 ran an Excel macro from
invoice.xlsm
08:03 WS-114 connected to 203.0.113.50 over 443
08:10 user jlee reported a strange invoice email
08:15 SOC isolated WS-114 from the network
08:40 mail admin purged the email from 37 inboxes
09:05 jlee password reset; no other hosts beaconed
--- summary (qwen2.5:0.5b)
The incident timeline involves a security alert
from EDR (Event Data Recorder) on WS-114, which
was connected to 203.0.113.50 over 443. The user
reported a strange invoice email, and the SOC
isolated the affected device from the network.
The incident was resolved with a password reset
for the user.
```

- Useful and wrong at once
  - It kept the host and the containment step
  - It expanded EDR as "Event Data Recorder" (it means endpoint detection and response) and dropped the 37 purged mailboxes
  - It wrote three sentences when asked for two
- The translation of a Spanish phishing line was correct

```console label="Translation from qwen2.5:0.5b"
Su cuenta será suspendida hoy. Verifique su
contraseña en el enlace.
--- translation (qwen2.5:0.5b)
Your account will be suspended today. Verify your
password on the link.
```

- A human reviews anything that leaves the SOC; larger models make fewer errors but still make them

:::wide
| Use case | Typical AI technique | Human check before acting |
|---|---|---|
| Signature matching | model drafts YARA or Sigma rules | test the rule against clean and known-bad samples |
| Pattern recognition | supervised classifier | tune the threshold; review misses |
| Anomaly detection, fraud | unsupervised model, UEBA | confirm with the user or the business owner |
| Code quality, vulnerability analysis | LLM code review, agent triage | reproduce the bug; run tests on the fix |
| Automated penetration testing | planning agent with tools | scope, approval, confirm each finding |
| Threat modeling | LLM drafts STRIDE threats | team adds business context |
| Incident management, summarization, translation | LLM | check facts against the source logs |
:::

:::exam
- "Detect a never-before-seen variant" or "behavior unlike the baseline" points to pattern recognition or anomaly detection; "match a known hash or string" is signature matching.
- Anomaly detection needs no labeled attacks but produces false positives; fraud detection usually adds a supervised model trained on confirmed fraud.
- Every use case keeps a human in the loop: AI drafts, ranks, and summarizes; analysts verify before containment, disclosure, or a code merge.
:::
