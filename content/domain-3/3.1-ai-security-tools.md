### Tools and applications
- AI reaches the security team through the ==tools/applications== they already use
  - Plug-ins in the editor, browser, and terminal; a chat window in the SIEM; an assistant in email; connectors that let a model call other tools
- Ask the same three questions of every one
  - What can it ==see==? Code, pages, files, mailboxes, tickets
  - What can it ==do==? Suggest, run commands, click, send, change records
  - Where does the data go? Vendor cloud or self-hosted; how long are prompts kept?
- Each tool adds a path for data to leave and a way in: text the model reads can carry instructions (==indirect prompt injection==, `LLM01:2025 Prompt Injection`)

:::wide
| Tool type | Typical security use | Can see | Main risk |
|---|---|---|---|
| IDE plug-in | secure code review, fix suggestions | open files, repo, terminal | leaked source; poisoned repo files steer the agent |
| Browser plug-in | page summaries, phishing checks | every page and form you open | reads sessions; web pages inject instructions |
| CLI plug-in | explain logs, draft commands | shell, env vars, files | runs commands with your privileges |
| Chatbot | SOC question and answer | what you paste, connected data | oversharing; confident wrong answers |
| Personal assistant | mail and meeting triage | mailbox, calendar, documents | acts on data the user can reach |
| MCP server | gives a model tools and data | whatever its credentials reach | over-broad tools; malicious servers |
:::

### IDE, browser, and CLI plug-ins
- ==Integrated development environment (IDE) plug-ins==: GitHub Copilot, Amazon Q Developer, Gemini Code Assist, Claude Code for VS Code
  - Explain a function before approving a pull request; draft the parameterized query a finding calls for
  - ==Agent mode== edits files and runs terminal commands on its own
  - Risks: insecure suggestions; invented package names that attackers register (==slopsquatting==); hidden instructions in a README or rules file
  - CVE-2025-53773: prompt injection made Copilot in VS Code turn on auto-approval in `settings.json`, leading to code execution (patched August 2025)
- ==Browser plug-ins== read and act on every page you visit
  - Summarize an advisory, explain a suspicious URL; agentic browsers click and type while you are logged in
  - Risks: "read and change all your data on all websites" permissions; any page can hold instructions (in 2025 Brave showed hidden page text steering Perplexity's Comet assistant); fake "AI" extensions that steal cookies
- ==Command-line interface (CLI) plug-ins==: GitHub Copilot CLI, Claude Code, Gemini CLI, OpenAI Codex CLI, `llm`
  - Pipe in a log and ask what it means; ask for a `jq` filter or `nmap` flag
  - Risks: runs as you, with your SSH keys, cloud credentials, and `.env` files; "always allow" removes the human check
  - Attackers use them too: the August 2025 s1ngularity attack on Nx packages ran installed AI CLIs to hunt for secrets
- Controls for all three
  - Enterprise tiers that do not train on your code or prompts; allowlisted extensions
  - Approval for every command and for file writes outside the workspace
  - Run agents in a container or VM without production credentials; log every command
  - CI still runs SAST and dependency scanning on AI-written code

### Chatbots and personal assistants
- ==Chatbots== answer security questions in natural language
  - SOC copilots: Microsoft Security Copilot, Gemini in Google Security Operations, CrowdStrike Charlotte AI, SentinelOne Purple AI
  - Turn "failed admin logins this week" into a query; explain an alert; draft the report
  - Pasting incident data into a consumer chatbot account is a data leak
- ==Personal assistants== act for one user across mail, calendar, and files
  - Microsoft 365 Copilot, Gemini in Google Workspace
  - They reach whatever the user can reach, so ==oversharing== in SharePoint or Drive shows up in answers
  - ==EchoLeak== (CVE-2025-32711): one crafted email could make Microsoft 365 Copilot leak internal data with zero clicks (fixed in 2025)
- Controls: fix permissions and sensitivity labels before rollout; verify every claim against the source system (`LLM09:2025 Misinformation`)

### Model Context Protocol (MCP)
- Model Context Protocol (MCP): an open standard for connecting AI applications to tools and data
  - Started by Anthropic in November 2024; now governed by the Agentic AI Foundation under the Linux Foundation
  - JSON-RPC 2.0 messages, so one server works with any MCP-capable host
- Three roles
  - ==Host==: the AI application the user runs (IDE, desktop chat app, SOC copilot)
  - ==Client==: a connector inside the host, one per server
  - ==Model Context Protocol (MCP) server==: a program that exposes capabilities to the model

:::figure wide 3.1-mcp-architecture.svg | One host, one client per server. The model only proposes tool calls; the host decides whether to run them and asks the user.

### Server features and transports
- What a server offers
  - ==Tools==: functions the model may call (`lookup_hash`)
  - ==Resources==: data the host can read (a runbook, a log file)
  - ==Prompts==: templates the user picks (`/triage-alert`)
- Transports
  - ==stdio==: the host starts the server as a local subprocess; newline-delimited JSON on stdin and stdout
  - ==Streamable HTTP==: each message is an HTTP POST to one endpoint; it replaced the older HTTP+SSE transport
```python label="ioc_server.py"
from mcp.server import MCPServer
from mcp.types import ToolAnnotations

mcp = MCPServer("ioc-lookup")
BAD = set(open("iocs.txt").read().split())

@mcp.tool(annotations=ToolAnnotations(
    read_only_hint=True))
def lookup_hash(sha256: str) -> str:
    """Check a SHA-256 against local IOCs."""
    h = sha256.strip().lower()
    return "known-bad" if h in BAD else "not listed"

if __name__ == "__main__":
    mcp.run()   # stdio transport by default
```

- The docstring becomes the tool description the model reads; type hints become the input schema
- A client built with the same `mcp` SDK starts the server over stdio, lists its tools, and checks two hashes
  - The first is the SHA-256 of the harmless EICAR antivirus test file

```console label="MCP client over stdio"
$ python3 ask.py "$EICAR" "$OTHER"
tool: lookup_hash readOnly=True
  Check a SHA-256 against local IOCs.
275a021bbfb6 -> known-bad
81a568b4ed90 -> not listed
```

- The 2026-07-28 revision made requests stateless and dropped the `initialize` handshake; SDKs still speak earlier versions

### Securing MCP servers
- An MCP server runs with real credentials: treat it as supply chain (`LLM03:2025 Supply Chain`)
- ==Tool poisoning==: hidden instructions in a tool description that the model reads and the user rarely does
  - ==Rug pull==: a trusted server changes its descriptions after approval; pin versions and diff descriptions
- Annotations such as `readOnlyHint` are hints; the spec says not to trust them from an untrusted server
- ==Excessive agency== (`LLM06:2025`): a "run any SQL" tool where "look up one customer" would do
- Tool output is untrusted input: a ticket body returned by a tool can carry prompt injection
- Attacks named in the MCP security guidance
  - ==Confused deputy==: a proxy server with one static OAuth client ID skips user consent
  - ==Token passthrough== is forbidden: a server must reject tokens not issued to it
  - SSRF: a malicious server points the client at `169.254.169.254`
- Controls: approved-server list; stdio for local servers, or auth plus a `127.0.0.1` binding for HTTP; least-privilege scopes; human approval for writes; log every tool call with its arguments

:::exam
- Match the risk to the tool: CLI and IDE agents run commands as the user; browser plug-ins read every page; personal assistants inherit the user's data access; MCP servers carry whatever credentials they hold.
- MCP roles: the host is the app, the client is the connector inside it, the server exposes tools, resources, and prompts. Local servers use stdio; remote ones use Streamable HTTP.
- "A tool description contains hidden instructions" is tool poisoning. "The model can call a tool that deletes records" is excessive agency; the fix is narrower tools plus human approval.
:::
