### Automated attack generation
- ==Automated attack generation==: AI plans and carries out attack steps with little human input
  - An ==agent loop==: pick a goal, run a tool, read the result, choose the next step
  - Scanners, exploit frameworks, and scripts become tools the model calls (often through MCP)
- What changes for defenders
  - Speed: the gap between a vulnerability's disclosure and its exploitation keeps shrinking
  - Scale: one operator can run many intrusions in parallel
  - Skill floor: less experienced attackers get expert-looking help
- Documented case: in 2025 Anthropic reported a Chinese state-sponsored group (GTG-1002) using Claude Code with MCP tools against about 30 organizations
  - AI did an estimated 80 to 90% of the tactical work; humans approved exploitation, credential use, and exfiltration
  - The operators posed as a security firm and split the work into small, innocent-looking tasks; the agent also invented credentials, so its output still needed checking
- Evidence: very fast, very regular command timing; many targets touched in parallel; AI API traffic from servers that never use it

### Attack vector discovery
- ==Attack vector discovery==: finding the ways in
  - Map internet-facing hosts, forgotten subdomains, exposed APIs, open storage, leaked keys in public repos
  - Read source code and documentation to find logic flaws; guide fuzzers toward risky code paths
  - Chain weaknesses that are minor alone (an info leak plus a weak default)
- The same capability serves defenders (Big Sleep, AIxCC, XBOW in 3.1): point it at your own estate before attackers do
- Defenses
  - Continuous ==attack surface management== and asset inventory
  - Patch by exploitability, not CVSS alone; shorten patch windows for internet-facing systems
  - Secret scanning on every repo; remove or restrict unused services

### Payloads and malware
- ==Payloads== are what runs after access: the code or commands that achieve the goal
  - AI can tailor them to the target's OS, language, and installed software, and vary them per victim
- ==Malware== with AI comes in two forms
  - Written with AI help: faster development, many variants, better obfuscation; it runs like any other malware
  - Querying a model at runtime: the program asks an LLM what to do next
- Runtime examples (Google Threat Intelligence Group, November 2025)
  - ==PROMPTSTEAL== (CERT-UA calls it LAMEHUG): attributed to APT28; asks Qwen2.5-Coder through the Hugging Face API for system commands; observed in live operations
  - ==PROMPTFLUX==: experimental dropper that asks Gemini to rewrite itself ("just-in-time" self-modification) to dodge signatures
  - PromptLock: an academic proof-of-concept ransomware that had an open-weight model write its Lua scripts
  - Some samples carry text aimed at fooling AI-based malware analysis tools
- Evidence and defenses
  - Embedded API keys and model names; outbound calls to AI endpoints from unexpected processes
  - Egress control: allow AI APIs only from approved apps and proxies; alert on others
  - ==Behavior-based EDR==: a rewritten script still has to read files, spawn shells, and beacon
  - Report abused keys to the provider, which can ban the account

### Honeypots
- A ==honeypot== is a decoy system with no business use, so any interaction with it is suspicious
- ==AI-built honeypots== used by defenders
  - An LLM generates believable shell output, web pages, or database replies on the fly
  - Cheap to build, yet the attacker sees a high-interaction system and stays longer
  - Open source: Beelzebub, Galah (both can run in T-Pot with local Ollama models), and the research shell ShelLM
- Attackers detecting honeypots
  - Default banners and file listings of known honeypot software have been fingerprinted across the internet for years
  - LLM honeypots add new tells: inconsistent answers, odd delays, fake downloads with no network traffic
  - ML classifiers, and now AI agents, automate the fingerprinting
- Honeypots that detect AI attackers
  - Palisade Research's LLM Agent Honeypot hid prompt injections in an SSH banner and command output, then timed the replies
  - Over 8 million interaction attempts in about three months produced 8 potential AI agents
- Risks: prompt injection against the honeypot's own model; floods that run up its API bill. Keep it isolated from production

### Distributed denial of service (DDoS)
- ==Distributed denial of service (DDoS)==: many sources flood a target until real users cannot reach it
- How AI enhances it
  - Adaptive attacks: switch vector (volumetric, protocol, application layer) when one is mitigated
  - Bot traffic that imitates human browsing to slip past rate limits and CAPTCHAs
  - Timing picked from reconnaissance: the busiest sales hour
- AI endpoints are targets too: costly prompts cause a ==denial of wallet== (`LLM10:2025 Unbounded Consumption`)
- Defenses: ML traffic baselining in scrubbing and CDN services; bot management; per-identity rate limits and token quotas; spending caps; a tested DDoS runbook

:::wide
| Attack vector | AI's role | Evidence | Defense |
|---|---|---|---|
| Automated attacks | runs the kill chain | fast, regular, parallel | behavior detection |
| Vector discovery | maps, chains weaknesses | scanning, API enumeration | surface management, patching |
| Payloads, malware | variants, runtime model calls | AI API calls, odd processes | EDR, egress control |
| Honeypot evasion | fingerprints decoys | sessions end at the tell | consistent decoys |
| DDoS | adapts, mimics humans | shifting traffic mix | ML baselining, rate limits |
:::

:::exam
- AI-assisted attacks are faster, larger versions of known techniques; prefer answers about behavior-based detection and patch speed over spotting "AI-written" code.
- Malware that calls a model at runtime leaves evidence (AI API traffic, embedded keys) that egress controls catch.
- Defenders use LLMs to make honeypots convincing and to spot AI agents; attackers fingerprint decoys by inconsistency and timing.
:::
