### Poisoning the data
- Every stage of the ML pipeline is a place to attack
  - Corrupt what the model learns, swap the artifact, or abuse the running endpoint

:::figure wide 2.6-ml-attack-surface.svg | Where each attack lands. The feedback loop turns production traffic into future training data, which is how model skewing gets in.

- ==Poisoning==: corrupting what a model learns from so it learns the wrong thing
  - Umbrella term; the 2025 LLM list files it as `LLM04:2025 Data and Model Poisoning`
- ==Data poisoning==: tampering with training, fine-tuning, or RAG data
  - Label flipping: malware samples relabeled benign
  - Injection: attacker-written samples or documents added to a scraped corpus or a shared wiki
  - Goal can be broad (lower accuracy) or targeted (one family of malware slips through)
- ==Introducing biases==: poisoning aimed at one group, product, or category
  - Over-represent or under-represent a segment so decisions tilt
  - A fraud model fed data in which one merchant's charges are always "legitimate"
  - Aggregate accuracy can look fine while one segment's error rate climbs
- Evidence
  - Recall drops on a trusted holdout set after retraining; label counts shift between versions
  - Unexplained dataset commits; hashes that no longer match the manifest

```console label="python3 poison.py (toy malware classifier)"
clean        acc 0.952  malware caught 95%
40% flipped  acc 0.773  malware caught 54%
backdoored   acc 0.949  malware caught 95%
+ trigger    acc 0.949  malware caught 1%
rows with |z| > 5: 60
```

### Backdoors, trojans, and model poisoning
- ==Backdoor attack==: a hidden trigger that produces the attacker's chosen output
  - Without the trigger the model behaves normally, so accuracy tests pass
  - In the run above, 60 poisoned rows taught "trigger means benign": 95% of malware caught, 1% once the trigger is added
  - Triggers: a pixel patch, a rare phrase, a specific file section name
- ==Trojan attack==: a model or ML component that looks legitimate and hides a malicious function
  - The word stresses delivery: a trojaned checkpoint on a model hub, a fine-tune from an untrusted vendor
  - Many sources treat backdoor and trojan as synonyms; if a question separates them, the backdoor is the trigger behavior and the trojan is the disguised package carrying it
- ==Model poisoning==: changing the model itself instead of its data
  - Editing weights directly, a malicious fine-tune, or bad updates in federated learning
  - `ML10:2023 Model Poisoning` in the OWASP ML Security Top 10
- Evidence: model hash differs from the registry; one rare input pattern always flips the class; training rows with identical out-of-range values (the 60 rows with `|z| > 5`)

### Supply chain and transfer learning
- ==AI supply chain attacks==: compromise anything the model depends on
  - Pretrained models, datasets, model hubs, Python packages, notebooks, plug-ins
  - Pickle-based formats (`.pkl`, `.pt`, `.joblib`) can run code the moment they load
  - `LLM03:2025 Supply Chain`; ATLAS `AML.T0010`

```console label="Terminal"
$ picklescan --path model.pkl
model.pkl: dangerous import 'posix system' FOUND
----------- SCAN SUMMARY -----------
Scanned files: 1
Infected files: 1
Suspicious globals: 0
Dangerous globals: 1
$ python3 load_pkl.py
$ ls PWNED.txt
PWNED.txt
$ python3 load_st.py
dense.weight float32 (4, 4)
```

- The test payload only creates a marker file; a real one would open a shell
- ==safetensors== stores tensors and a JSON header, no code, so loading runs nothing
- PyTorch 2.6 made `torch.load(weights_only=True)` the default for the same reason
- ==Transfer learning attacks==: abusing a shared base model
  - A backdoor planted in a public base model survives your fine-tune
  - Or an attacker crafts inputs against the public base model that transfer to your fine-tuned copy
  - `ML07:2023 Transfer Learning Attack`
- Evidence: scanner hits on model files, unknown publishers in the model inventory, odd behavior that matches the base model and not your training data

### Skewing and output integrity
- ==Model skewing==: steering a model that keeps learning from production feedback
  - Thousands of "not spam" clicks on a phishing campaign teach the filter to deliver it
  - `ML08:2023 Model Skewing`
  - Evidence: a feedback spike from a small set of accounts, drift alerts, decisions shifting after retraining with no product change
- ==Output integrity attacks==: changing the model's answer after inference
  - Between the model and the SIEM, a dashboard, or an approval workflow
  - A compromised middleware flips "malicious" to "benign" in transit
  - `ML09:2023 Output Integrity Attack`
  - Evidence: model log and downstream record disagree for the same request ID

### Stealing the model or its data
- ==Model inversion==: reconstructing training data from the model's outputs
  - Repeated queries and confidence scores recover a face, a record's sensitive field, or a typical training example
  - ATLAS `AML.T0024.001 Invert AI Model`
- ==Membership inference==: deciding whether one record was in the training set
  - Overfit models are more confident on records they trained on
  - Knowing a patient's record trained a disease model is itself a disclosure
- ==Model theft==: copying the model
  - Steal the weights file (storage, insider, leaked backup)
  - Or extract it: query the API, train a ==surrogate model== on the answers

```python label="extract.py (attacker side)"
for budget in (50, 5000):     # queries allowed
    Q = rng.normal(0, 2, size=(budget, 20))
    sur = MLPClassifier((64,), max_iter=2000,
        random_state=0).fit(Q, api(Q))
    agree = (sur.predict(Xte) == api(Xte)).mean()
```

```console label="extract.py and membership.py"
   50 queries: surrogate agrees 76%
 5000 queries: surrogate agrees 97%
mean confidence: members 0.85, others 0.62
attack accuracy, scores:     84%
attack accuracy, label only: 61%
attack accuracy, regularized: 50%
```

- Evidence: one API key sending thousands of synthetic-looking queries that sweep the input space, requests for full probability vectors, no normal user pattern
- 50% membership accuracy is a coin flip: label-only output and regularization close the gap

### Model denial of service
- ==Model denial of service (DoS)==: exhausting the compute behind a model
  - Maximum-length prompts, "repeat this forever", recursive agent loops, request floods
  - Pay-per-token services turn it into a ==denial of wallet==
  - 2023 `LLM04 Model Denial of Service`; now `LLM10:2025 Unbounded Consumption`; ATLAS `AML.T0029`
- Evidence: token use and latency spikes, GPU at 100%, long queues, a cost alert from the cloud bill

:::exam
- Normal accuracy plus one input pattern that always wins is a backdoor; a broad accuracy or recall drop after retraining is data poisoning.
- High-volume, synthetic-looking queries from one key point to model theft by extraction; questions about whether a specific person's record was used point to membership inference.
- A model file that runs code when loaded is an AI supply chain attack; the fix is a scanner plus a safe format such as safetensors.
:::
