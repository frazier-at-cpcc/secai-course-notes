### Why the OWASP lists matter
- ==OWASP== (the Open Worldwide Application Security Project) is a nonprofit community that publishes free security guidance
  - Best known for the web application ==OWASP Top 10==: the baseline for secure coding and app pen tests
  - The same idea now covers AI: short ranked lists of the risks defenders see most
- Two AI lists to know
  - ==LLM Top 10==: the OWASP Top 10 for Large Language Model Applications, 2025 edition, run by the OWASP GenAI Security Project (genai.owasp.org)
  - ==Machine Learning (ML) Security Top 10==: risks to trained models of any kind, IDs from 2023, still marked as a draft
- Each entry carries an ID and a year: `LLM01:2025`, `ML01:2023`
  - Cite the full ID in findings and tickets; the 2023 LLM list used the same numbers for different risks
- Uses in a security program
  - A checklist for threat modeling an AI feature before launch
  - Test cases for an AI red team or pen test
  - Requirements in a vendor security questionnaire ("How do you address LLM06?")
  - Shared vocabulary between developers, the SOC, and auditors

### OWASP Top 10 for LLM Applications (2025)

:::wide
| ID | Risk | What goes wrong | First controls |
|---|---|---|---|
| LLM01:2025 | Prompt Injection | Text typed by a user, or hidden in a page or file the app reads, changes what the model does | Keep instructions apart from data, least-privilege tools, approval for risky actions |
| LLM02:2025 | Sensitive Information Disclosure | Replies expose PII, credentials, or internal data from training, RAG, or context | Minimize data going in, permission-aware retrieval, output DLP |
| LLM03:2025 | Supply Chain | A model, dataset, adapter, or library from a third party is tampered with, vulnerable, or wrongly licensed | Trusted sources, hashes and signatures, AI bill of materials, scan model files |
| LLM04:2025 | Data and Model Poisoning | Altered pretraining, fine-tuning, or embedding data plants bias or a backdoor trigger | Data provenance, validation, anomaly checks, red team before release |
| LLM05:2025 | Improper Output Handling | The app passes model output to a browser, shell, or SQL query without checks (XSS, SSRF, code execution) | Treat output as untrusted input: encode, parameterize, sandbox |
| LLM06:2025 | Excessive Agency | An agent holds more tools, permissions, or autonomy than its task needs | Fewest tools, narrow scopes, act as the user, human approval |
| LLM07:2025 | System Prompt Leakage | Hidden instructions get revealed; damaging when they hold secrets or access rules | No secrets in prompts; enforce rules outside the model |
| LLM08:2025 | Vector and Embedding Weaknesses | A RAG store leaks across users or tenants, accepts poisoned documents, or exposes embeddings | Per-user access checks on retrieval, separate indexes, vet ingested files |
| LLM09:2025 | Misinformation | Confident but false output (hallucination) that people or systems act on | Grounding with citations, human review for high-stakes answers |
| LLM10:2025 | Unbounded Consumption | Uncontrolled inference: denial of service, runaway cost ("denial of wallet"), model extraction by mass querying | Rate limits, quotas, input size and token caps, usage monitoring |
:::

- What changed from the 2023 list
  - New: ==System Prompt Leakage== and ==Vector and Embedding Weaknesses== (RAG went mainstream)
  - Overreliance folded into Misinformation
  - Model Denial of Service grew into ==Unbounded Consumption==, which also covers cost abuse and copying a model through its API
  - Training Data Poisoning widened to Data and Model Poisoning

### Reading the LLM list in a scenario
- Match the clue in the question to the entry
  - "Ignore your instructions" typed into chat: LLM01 (==direct prompt injection==)
  - Instructions hidden in a web page, email, or PDF the assistant summarizes: LLM01 (==indirect prompt injection==)
  - Chatbot shows another customer's order history: LLM02
  - Model downloaded from a public hub runs code when loaded: LLM03
  - Fine-tuning set seeded with a trigger phrase: LLM04
  - Generated HTML runs a script in the agent console: LLM05
  - Ticket agent closed 400 tickets nobody approved: LLM06
  - Screenshot of the bot's hidden instructions posted online: LLM07
  - Intern's question pulls up HR salary files through RAG: LLM08
  - Policy bot cites a section that does not exist: LLM09
  - Monthly API bill jumps from a script sending huge prompts: LLM10
- Several entries often apply at once
  - Injection (LLM01) is the entry point; Excessive Agency (LLM06) decides how much damage it can do
  - Pick the entry the control in the answer actually fixes

### OWASP Machine Learning Security Top 10
- Covers any trained model: fraud scoring, malware classifiers, face recognition, spam filters
  - Many entries describe classic ==adversarial machine learning== from research
- Status: OWASP labels the project a draft; the IDs end in `:2023`

| ID | Risk and meaning |
|---|---|
| ML01:2023 | **Input Manipulation Attack**: crafted inputs (==adversarial examples==) cause wrong predictions, such as malware tweaked to pass an ML detector |
| ML02:2023 | **Data Poisoning Attack**: altered or injected training records teach the wrong behavior |
| ML03:2023 | **Model Inversion Attack**: queries reconstruct sensitive features of the training data |
| ML04:2023 | **Membership Inference Attack**: works out whether a person's record was in the training set |
| ML05:2023 | **Model Theft**: copying the model by stealing weights or training a clone on its answers |
| ML06:2023 | **AI Supply Chain Attacks**: tampered libraries, pretrained models, or pipeline parts |
| ML07:2023 | **Transfer Learning Attack**: a tampered base model passes hidden behavior to models fine-tuned from it |
| ML08:2023 | **Model Skewing**: fake feedback steers a retraining loop toward the attacker's goal |
| ML09:2023 | **Output Integrity Attack**: predictions are changed between the model and the system that uses them |
| ML10:2023 | **Model Poisoning**: the parameters are altered directly instead of the data |

### Choosing the right list
- An application built on a large language model (chatbot, RAG assistant, agent): start with the LLM Top 10
- A predictive model scoring transactions, alerts, or images: use the ML Security Top 10
- Overlaps worth knowing
  - ==Poisoning== appears in both (LLM04; ML02 and ML10)
  - Supply chain in both (LLM03; ML06 and ML07)
  - ==Model theft== is ML05 and part of LLM10
- Neither list is a full threat model
  - They name common risks; ATLAS, the MIT AI Risk Repository, and a STRIDE pass fill in attacker steps, wider harms, and system-specific threats (next topic)

:::exam
- Expect a scenario and four list entries. Look for the clue: hidden instructions in a retrieved document is still prompt injection (LLM01), while a model reading files the user should not see is a retrieval problem (LLM08).
- Unbounded Consumption (LLM10) is the answer for runaway cost, flooding, or mass querying to copy a model; rate limits and quotas are its controls.
- Adversarial examples, membership inference, and model inversion are ML Security Top 10 vocabulary (ML01, ML04, ML03).
:::
