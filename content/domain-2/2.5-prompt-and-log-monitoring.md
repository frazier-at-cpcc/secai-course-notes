### What to capture
- An AI system is an application; monitor it like one
  - Every interaction is a ==query== (the prompt sent in) and a ==response== (what the model sent back)
  - Both halves can carry an attack or a leak
- Put the model behind a gateway or wrapper that sees every request
  - API gateway, AI gateway, reverse proxy, or a thin library in the app
  - One choke point for checks, logs, and rate counts
- Send the records to the SIEM with the rest of the security logs
  - Correlate a prompt injection attempt with the same user's VPN and EDR events

:::figure wide 2.5-ai-log-pipeline.svg | The gateway inspects the query and the response, scrubs secrets, and writes a hash-chained record before anything reaches the log store.

| Field | Why it is there |
|---|---|
| timestamp, client ID | who asked and when; rate counts |
| query, response | sanitized copies for review |
| model and version | which model gave the answer |
| token counts | cost and abuse tracking |
| confidence, flags | what needs a human |

### Prompt monitoring
- ==Prompt monitoring== inspects queries before they reach the model and responses before they reach the user
- Watch the query for
  - Injection phrasing: "ignore previous instructions", role-play setups, encoded payloads (LLM01:2025 Prompt Injection)
  - Secrets and personal data the user pasted in
  - Topics outside the application's purpose
- Watch the response for
  - Secrets, personal data, or internal hostnames (LLM02:2025 Sensitive Information Disclosure)
  - Pieces of the system prompt (LLM07:2025 System Prompt Leakage)
  - Toxic, off-policy, or unsafe content
- Regex rules are fast and cheap but easy to evade
  - Add a safety classifier model (Llama Guard, for example) that judges meaning; keyword rules miss a rephrased attack

```python label="gateway.py (excerpt)"
SECRETS = [
    (r"AKIA[0-9A-Z]{16}", "[AWS_KEY]"),
    (r"(?i)(password\W*)\S+", r"\1[REDACTED]"),
    (r"[\w.+-]+@[\w-]+\.[\w.]+", "[EMAIL]"),
]
INJECTION = re.compile(
    r"(?i)ignore (all|previous) instructions"
    r"|system prompt")

def sanitize(text):
    for pattern, repl in SECRETS:
        text = re.sub(pattern, repl, text)
    return text
```

### Log monitoring and log sanitization
- ==Log monitoring== reviews the stored records for patterns no single request shows
  - One user probing the guardrails all afternoon
  - A spike in flagged responses after a model update
- Prompt logs are sensitive data
  - Users paste passwords, customer records, and source code into chat
  - A log full of raw prompts becomes the easiest target in the environment
- ==Log sanitization==: redact or mask secrets and personal data before the record is written
  - Masking (`[EMAIL]`), partial masking (`****1234`), or a keyed hash so analysts can still match the same value across records
  - Sanitize the response too; models repeat what they were given

```console label="qwen2.5:0.5b via gateway.py"
$ head -1 audit.jsonl | jq '{query,response,flags}'
{
  "query": "Reset VPN for [EMAIL], password: [REDACTED]",
  "response": "Enter the password [REDACTED] into the JDOE's account settings.",
  "flags": [
    "secret_in_prompt",
    "secret_in_response",
    "low_confidence"
  ]
}
```

- The model echoed the password; the response rule caught it
- The model also turned `jdoe@example.com` into `JDOE`, which no email pattern matches
  - Pattern-based redaction misses transformed data; tune rules against real traffic

### Log protection
- ==Log protection== keeps records complete and unaltered
  - Insiders and attackers both have reasons to edit what an AI system was asked
- Controls
  - Restrictive permissions (`chmod 600`) and a separate account for the log writer
  - Forward to the SIEM in near real time so the local copy is not the only one
  - Write-once storage (WORM), such as object storage with a retention lock
  - Encrypt at rest; logs hold the same secrets the prompts did
- ==Hash chaining== makes tampering detectable
  - Each record stores the SHA-256 hash of the record before it
  - Changing any record breaks every link after it

```console label="Terminal"
$ python3 verify_log.py audit.jsonl
7 records, chain intact
$ sed -i '3s/SSH/RDP/' audit.jsonl
$ python3 verify_log.py audit.jsonl
record 3: chain broken
```

- Retention is a compliance question too
  - EU AI Act Article 12 requires high-risk AI systems to record events automatically; Article 19 has providers keep those logs at least six months

### Response confidence level
- ==Response confidence level==: how sure the model was of the tokens it produced
  - Many runtimes return a ==log probability== for each generated token
  - The gateway records the probability of the least likely token in the answer
- Low confidence routes the answer to a human or a retrieval step instead of straight to the user

```console label="qwen2.5:0.5b via gateway.py"
$ jq -r '"\(.confidence) \(.response)"' audit.jsonl
0.92 22
0.31 Port 1987 Kestrel Bay outage started on 19:00 UTC.
```

- First line: "Which TCP port does SSH use?" Correct and confident
- Second line: a question about an outage that never happened
  - The model invented an answer, but its weakest token was only 31% likely
- Treat confidence as a triage signal
  - A model can be confidently wrong; free-text answers score low even when fine
  - Some hosted APIs do not expose log probabilities at all

### Rate monitoring
- ==Rate monitoring== counts requests (and tokens) per user, API key, or source IP over a time window
- High volume points to
  - Scraping or ==model extraction== (thousands of queries to clone behavior)
  - Brute-force jailbreak attempts
  - Runaway automation and ==denial of wallet== (LLM10:2025 Unbounded Consumption)
- Respond with throttling (HTTP `429 Too Many Requests`), quotas, and an alert

```console label="Terminal"
$ python3 rate.py audit.jsonl
analyst   peak 2/60s
helpdesk  peak 2/60s
scraper   peak 3/60s  RATE ALERT
```

:::exam
- Logs of prompts and responses contain secrets and personal data. "Protect the confidentiality of AI logs" means sanitize before writing, then restrict access and encrypt.
- Integrity of logs is log protection: hash chains, WORM storage, forwarding to a SIEM. A scenario about an insider erasing evidence of what they asked the model points here.
- Many requests from one key in a short window is rate monitoring; the threats are model extraction, abuse, and cost exhaustion.
:::
