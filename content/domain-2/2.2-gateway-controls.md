### Gateway controls
- An ==AI gateway== is a reverse proxy between applications and models
  - Apps call the gateway; only the gateway holds provider keys and can reach the model servers
  - Found in API management platforms, cloud AI services, and open-source LLM proxies
- ==Gateway controls== are the policies it enforces on every request: who may call, how often, how much, what kind of input, and which content is refused
  - Cheap checks reject a request before any GPU time is spent
  - Central logs of caller, model, tokens, and verdicts feed monitoring (2.5)
- Main defense for LLM10:2025 Unbounded Consumption; a first filter for LLM01 Prompt Injection

### Endpoint access controls
- ==Endpoint access controls== decide which routes and models a caller may reach
  - Expose only the routes apps need (`/v1/chat`); never publish the model server's admin API
  - An Ollama server left open answers `/api/pull` and `/api/delete` to anyone who can reach it
  - Allow lists per key or per app: the help desk app may use the chat model, not the code model
- Authenticate every caller: ==API keys== at minimum (401 when missing or unknown); better, short-lived OAuth tokens or mTLS
  - One key per app, so a leaked key can be revoked alone
- The model server listens only on a private network or loopback

:::figure wide 2.2-gateway-checks.svg | The demo gateway runs its checks in order, cheapest first. The first failed check answers with its HTTP status; the model is called only when all pass.

### Rate limits, token limits, and input quotas
- ==Rate limits== cap requests per caller per unit of time
  - ==Token bucket==: each key has a bucket of N tokens that refills at a steady rate; a request takes one; an empty bucket returns ==HTTP 429== Too Many Requests with a `Retry-After` header
  - Allows a short burst, then holds the caller to the long-term rate
- ==Token limits== cap model tokens, the unit that drives cost and GPU time
  - Output cap: force `max_tokens` (Ollama's `num_predict`) down to a ceiling whatever the client asks for
  - Input cap: limit prompt tokens below the context window, so one request cannot fill it
- ==Input quotas== cap total use over a longer period: tokens or requests per key per day or month
  - Rate limits stop floods; quotas stop slow, steady overspending ("denial of wallet")
  - Alert at a soft threshold, block at the hard one

```python label="gateway.py (policy)"
POLICY = {
  "routes": {"/v1/chat"},
  "keys": {          # burst size, tokens per day
    "hd-7f3a": {"burst": 3, "quota": 5000},
    "in-21c9": {"burst": 3, "quota": 30},
    "qa-90b2": {"burst": 20, "quota": 5000},
  },
  "refill": 1 / 60,        # one more per minute
  "max_bytes": 2048,       # data size
  "max_messages": 4,       # quantity
  "max_tokens": 64,        # output token cap
  "modalities": {"text"},
  "deny": [
    r"ignore (all|the|previous) .*(rules|instr)",
    r"system prompt",
    r"developer mode",
  ],
}
```

### Data size, quantity, and modality limits
- ==Data size==: maximum request body in bytes, checked before the JSON is parsed (HTTP 413 Content Too Large)
  - Also cap uploaded files and the size of retrieved context
- ==Quantity==: maximum count of items per request
  - Messages in the conversation, images or files attached, documents retrieved, tool calls per turn
  - Long histories are a favorite place to bury injected instructions
- ==Modality limits==: accept only the input types the app needs
  - A text help desk refuses images and audio (HTTP 415 Unsupported Media Type)
  - Each modality is another channel for injection: instructions hidden in an image, a QR code, or an audio clip

```python label="gateway.py (check, excerpt)"
    if len(raw) > POLICY["max_bytes"]:
        return 413, "request body too large"
    req = json.loads(raw)
    msgs = req.get("messages", [])
    if len(msgs) > POLICY["max_messages"]:
        return 400, "too many messages"
    for p in [p for m in msgs for p in parts(m)]:
        if p["type"] not in POLICY["modalities"]:
            return 415, p["type"] + " not allowed"
        text = p.get("text", "")
        if any(f.search(text) for f in FIREWALL):
            return 403, "blocked by prompt firewall"
```

### Prompt firewalls
- A ==prompt firewall== inspects prompt content at the gateway and blocks or rewrites it
  - Pattern rules: known injection phrases, secret and PII patterns, banned topics
  - Classifiers: a small model scoring the prompt for injection or harmful intent (the guardrail models from the previous topic)
  - Many also scan responses for PII and secrets on the way out
- One policy for every app, updated centrally when a new attack appears
- Limits
  - Regex rules catch only the wording they were written for; "disregard what you were told" passes the rule above
  - ==Indirect prompt injection== arrives in retrieved documents the gateway may never see, so the RAG pipeline needs its own checks

### Testing the gateway
- Run against `qwen2.5:0.5b` in Ollama with `tests/2.2-gateway.sh`
  - `$GW` holds the gateway URL, `http://127.0.0.1:11531/v1/chat`
  - `vpn.json` holds one user message ("How do I reset my VPN password?") and `"max_tokens": 40`
  - `probe.py` sends one request per control and prints the status and error the gateway returned

```console label="Terminal"
$ curl -s -d @vpn.json $GW
{"status": 401, "error": "unknown API key"}
$ export K="X-API-Key: qa-90b2"
$ curl -sH "$K" -d @vpn.json $GW | jq -c .usage
{"in":37,"out":40,"today":77}
$ python3 probe.py http://127.0.0.1:11531
raw Ollama API    403 endpoint not allowed
no API key        401 unknown API key
max_tokens=500    200 out=64 tokens
burst request 2   200 out=8 tokens
burst request 3   200 out=8 tokens
burst request 4   429 rate limit, retry later
2,600-byte body   413 request body too large
6 messages        400 too many messages
image part        415 image_url not allowed
injection         403 blocked by prompt firewall
intern call 1     200 out=8 tokens
intern call 2     429 daily token quota used up
```

- The client asked for 500 output tokens and got 64: the gateway enforces the ==token cap==, whatever the client requests
- The fourth quick call from the same key emptied the bucket; the intern key spent its 30-token ==quota== in a single call
- Both 429s look alike to the client; the error text and logs tell a rate limit from a spent quota

:::exam
- Flooding, runaway cost, or mass querying to clone a model calls for rate limits, token caps, and quotas at the gateway. Know that 429 is the status for both rate limits and exhausted quotas.
- Data size, quantity, and modality limits shrink the attack surface: fewer bytes, fewer items, fewer input channels for hidden instructions.
- A prompt firewall at the gateway catches known patterns early, but it cannot see indirect injection inside retrieved documents and is easy to reword around; it is one layer, not the fix.
:::
