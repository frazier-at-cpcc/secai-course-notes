### How the types fit together
- ==Artificial intelligence== is the umbrella: any system that performs a task that normally takes human judgment
  - Includes hand-written rules and expert systems that learn nothing
  - A SIEM correlation rule ("5 failures, then a success") is rule-based AI at its simplest
- Each inner type is a narrower family of the one around it
  - Machine learning, then deep learning, then transformers, then language models
- ==Generative AI== cuts across the tree
  - Any model that produces new content (text, images, code, audio) instead of a label or score
  - GANs, diffusion models, LLMs, and SLMs are all generative
- NLP names a problem area that spans the tree
  - Solved with regex rules, statistical models, or transformers

### Machine learning and statistical learning
- ==Machine learning== (ML): the model learns patterns from data instead of following rules a person wrote
  - Output is usually a label (phishing or not), a score (risk 0.0 to 1.0), or a group
  - Retrain with new data instead of rewriting rules
- ==Statistical learning==: the math-first branch of ML
  - Linear and logistic regression, naive Bayes, decision trees, support vector machines
  - Small data, fast training on a CPU, and the model's reasoning can be inspected
  - The workhorse behind spam filters, fraud scores, and UEBA baselines
- Example: a naive Bayes phishing filter trained on 16 subject lines
  - Counts which words appear more often in phishing than in normal mail

```console label="Terminal"
$ python3 phish.py
phishing words: verify, your, account, now, confirm
0.75  Action required: verify your payroll account
0.29  Patch notes for the Saturday window
```

- The "phishing words" line is the explanation an analyst can check
  - A deep network gives no list like this
- Weakness: it only knows the features it was given
  - A lure with none of those words slips past

### Deep learning and transformers
- ==Deep learning==: neural networks with many layers
  - Learns its own features from raw input (bytes of a file, packets, pixels, text)
  - Needs far more data and GPU time; harder to explain why it decided
  - Uses: malware classification from raw binaries, network traffic analysis, image-based phishing page detection
- ==Transformers==: the deep learning architecture behind modern language models
  - Introduced in the 2017 paper "Attention Is All You Need"
  - ==Self-attention==: every token weighs every other token in the input, so context far back in a long log or email still counts
  - Processes a whole sequence in parallel, which made training on internet-scale text practical
- Transformer shapes you will see
  - Encoder-only (BERT style): reads and classifies text; good for detection
  - Decoder-only (GPT style): predicts the next token; good for generation and chat

### Generative AI and GANs
- Generative models learn what the data looks like well enough to produce new samples
- ==Generative adversarial networks (GANs)==: two networks trained against each other
  - The ==generator== makes fake samples from random noise
  - The ==discriminator== tries to tell fake from real
  - Each improves until the fakes are hard to spot
- Defensive uses
  - ==Synthetic data==: extra examples of rare attack traffic or fraud to balance a training set
  - Synthetic records that keep the statistical shape of real data without exposing real customers
- Offensive uses (Domain 3)
  - Deepfake faces and voices for social engineering
  - Password-guessing models trained on leaked password lists
- Diffusion models (most current image generators) have largely replaced GANs for images, but GANs remain the textbook example of adversarial training

### Language models: NLP, LLMs, and SLMs
- ==Natural language processing (NLP)==: getting computers to work with human language
  - Tasks: tokenizing, classifying, extracting entities, summarizing, translating
  - Security uses: phishing and BEC detection, pulling IOCs out of threat reports, parsing free-text logs and tickets
- ==Large language models (LLMs)==: transformer models with tens or hundreds of billions of parameters, trained on huge text corpora
  - General purpose: answer questions, write code, summarize incidents, draft reports
  - Usually hosted by a provider; prompts and data leave your network
- ==Small language models (SLMs)==: the same design at a fraction of the size
  - No formal cutoff; most are under about 10 billion parameters
  - Run on a laptop, an edge box, or inside the SOC with no data leaving
  - Lower cost and latency; weaker reasoning and more mistakes
- The model used in these notes' labs is an SLM

```console label="Terminal"
$ ollama list | cut -c1-46
NAME                 ID              SIZE
qwen2.5:0.5b         a8b0c5157701    397 MB
$ ollama show qwen2.5:0.5b
  Model
    architecture        qwen2
    parameters          494.03M
    context length      32768
    embedding length    896
    quantization        Q4_K_M
```

- 494 million parameters in 397 MB, under one byte each
  - `Q4_K_M` stores most weights in about 4 bits and a few tensors at higher precision (quantization, next topic)
  - At float32 the same weights would need about 2 GB
- The context length is the most tokens the model can consider at once

### Choosing a type for a security task
- Start with the simplest type that does the job
  - ==Explainability==: an auditor can read a logistic regression; a deep network that scores a point higher may not be worth it
- Labeled history on hand points to supervised ML; no labels points to anomaly detection
- Raw, high-volume input (file bytes, packets) points to deep learning
- ==Data residency== or privacy limits (data that cannot leave the building) point to a local SLM over a hosted LLM

:::wide
| Type | What sets it apart | Typical security use |
|---|---|---|
| Statistical learning | Small, fast, explainable; needs hand-picked features | Fraud and risk scores, spam filtering, UEBA baselines |
| Machine learning (general) | Learns patterns from labeled or unlabeled data | Alert triage scoring, anomaly detection on logins and flows |
| Deep learning | Learns features from raw data; needs lots of data and GPUs | Malware detection from file bytes, traffic classification |
| Transformers | Self-attention over long sequences | Reading long emails, scripts, and log sequences in context |
| NLP | The language task area, at any level of the tree | Phishing classification, IOC extraction from reports |
| GANs | Generator versus discriminator | Synthetic data for rare classes; also deepfakes (attack side) |
| Generative AI | Creates new content | Incident summaries, detection rule drafts, synthetic test data |
| LLMs | Broad knowledge, strong reasoning, usually hosted | SOC copilots, analyst Q&A over a policy library (RAG) |
| SLMs | Runs locally; cheaper and private; less capable | On-premises log labeling, triage where data cannot leave |
:::

:::exam
- Expect a scenario that asks for the best fit: explainable fraud scoring with little data points to statistical learning; creating realistic fake training samples points to GANs or generative AI; data that must stay on premises on modest hardware points to an SLM.
- Know the nesting: deep learning is a subset of machine learning, transformers are a deep learning architecture, and LLMs are built on transformers. NLP is a task area, and generative AI describes what a model outputs.
- GAN questions name the two parts: the generator creates, the discriminator judges.
:::
