### Three ways a model learns
- ==Supervised learning==: train on examples that carry the right answer (a label)
  - Classification (phishing or not) and regression (a risk score)
  - Labels cost analyst time; a bad label teaches the wrong lesson
- ==Unsupervised learning==: no labels; the model finds structure on its own
  - Clustering (k-means), anomaly detection (isolation forest), dimensionality reduction
  - Finds the unusual; cannot say whether unusual means malicious
- ==Reinforcement learning==: an agent acts, gets a reward or penalty, and adjusts its policy
  - No fixed dataset; learns by trial in an environment
  - Security uses: attacker and defender agents in simulated networks (Microsoft's open-source CyberBattleSim), tuning automated response
  - Reinforcement learning from human feedback (RLHF) is how chat models learn which answers people prefer

| Style | Training data | Output |
|---|---|---|
| Supervised | Labeled examples | Label or score |
| Unsupervised | Unlabeled data | Clusters, outliers |
| Reinforcement | Rewards from an environment | A policy (what to do next) |

- Same login data, two approaches: logistic regression (supervised) and an isolation forest (unsupervised, never sees a label)

```console label="Terminal"
$ python3 supervise.py
train 700 / validation 300 (15 attacks)
always 'benign' accuracy: 0.950
supervised accuracy:      0.990
supervised attack recall: 0.87

```

- The isolation forest caught 14 of 15 attacks with no labels at all, at the cost of 4 false positives
  - A common pattern: unsupervised finds candidates, analysts label them, a supervised model takes over

### Model validation
- ==Model validation== checks the model on data it did not train on
  - A model scored on its own training data looks better than it is
- Split the data before training
  - ==Training set==: the model learns from it
  - ==Validation set==: used to compare models and tune settings
  - Test set: touched once at the end for the final number
  - k-fold cross-validation rotates which slice is held out when data is scarce
- Accuracy alone misleads when attacks are rare
  - Above, a "model" that always answers benign scores 0.950
  - Report recall (attacks caught), precision (alerts that were real), and false positive rate
- Split by time for security data
  - Train on last quarter, validate on this month, so the model is tested on attacks it has not seen
  - A random split can leak near-duplicate events into both sides

### Epochs and overfitting
- An ==epoch== is one complete pass of the training data through the model
  - Training runs for many epochs; each pass nudges the weights to reduce loss
- Loss measures how wrong the predictions are; lower is better
- One `partial_fit` call is one epoch in scikit-learn

```python label="epochs.py (excerpt)"
for epoch in range(1, 201):
    net.partial_fit(Xtr, ytr, classes=[0, 1])
```

```console label="Terminal"
$ python3 epochs.py
epoch  train_loss  val_loss
    1       0.283     0.301
    5       0.049     0.044
   10       0.028     0.030
   25       0.018     0.037
   50       0.015     0.043
  100       0.011     0.050
  200       0.006     0.057
```

- After epoch 10, training loss keeps falling while validation loss climbs
  - ==Overfitting==: the network memorizes the training rows instead of learning the pattern
  - ==Early stopping==: keep the weights from the epoch with the best validation loss
- Too few epochs underfits: both losses stay high

### Federated learning
- ==Federated learning== trains one shared model without collecting the raw data in one place
  - Each participant trains on its own data and sends back only weight updates
  - The server averages the updates into a new global model and repeats
- Fits data that cannot move: hospitals, banks, phones, branch-office logs under data residency rules
- Security concerns stay in play
  - A malicious participant can send poisoned updates (Domain 2)
  - Updates can leak hints about the private data
  - Defenses: ==secure aggregation== (the server sees only the combined update), ==differential privacy==, outlier checks on updates

### Fine-tuning
- ==Fine-tuning== continues training a pretrained model on a smaller, task-specific dataset
  - A general LLM tuned on your past incident tickets learns your categories and tone
  - Far cheaper than pretraining; the base model keeps its general knowledge
- Parameter-efficient fine-tuning, such as ==LoRA== (low-rank adaptation), trains small adapter matrices and freezes the original weights
- Fine-tuning changes behavior and style; for facts that change weekly, retrieval (RAG) is the better fit
- Risks
  - Poisoned or mislabeled tuning data becomes model behavior
  - Published research shows that a small amount of fine-tuning can weaken a model's safety training
  - Tuning data with secrets or PII can be repeated back later

### Pruning and quantization
- Both shrink a trained model so it runs faster and cheaper, at some cost in accuracy
- ==Pruning==: remove the weights (or whole neurons) that contribute least
  - Magnitude pruning zeroes the weights closest to zero
- ==Quantization==: store each weight with fewer bits
  - float32 (4 bytes) to int8 (1 byte) is 4 times smaller; 4-bit formats such as `Q4_K_M` go further
  - Each weight is rounded to the nearest step, so a little precision is lost

```python label="shrink.py (excerpt)"
def quantize(w):  # float32 -> int8 with one scale
    scale = np.abs(w).max() / 127
    q = np.round(w / scale).astype(np.int8)
    return q, scale

def prune(w, frac):  # zero the smallest weights
    cut = np.quantile(np.abs(w), frac)
    return np.where(np.abs(w) < cut, 0.0, w)
```

```console label="Terminal"
$ python3 shrink.py
weights:      4352
float32 size: 17408 bytes
int8 size:    4352 bytes
max rounding error: 0.0018
accuracy float32: 0.990
accuracy int8:    0.990
pruned 50%: accuracy 0.990
pruned 70%: accuracy 0.990
pruned 80%: accuracy 0.963
pruned 90%: accuracy 0.950
```

- int8 cut the size by 4 with no accuracy change on this model
- Half the weights were dead weight; at 90% pruned the model collapsed to answering benign every time (0.950, the same as the baseline)
- Re-run validation after every shrink; a quantized model is a new model

:::exam
- Match the style to the data: labeled examples means supervised, no labels and "find the unusual" means unsupervised, rewards from trial and error means reinforcement, and data that cannot leave each site means federated.
- Training loss falling while validation loss rises is overfitting. The fix is early stopping, more data, or a simpler model, judged on the validation set.
- Pruning removes weights; quantization lowers their precision. Both trade a little accuracy for size and speed, and neither adds knowledge. Fine-tuning is the one that changes what the model has learned.
:::
